# School Site — Project Memory

Demo school website built with **Next.js 16 + Payload CMS 3**. This is a practice
build that will be cloned into a real **church website** afterward, so keep the
structure clean, generic, and reusable.

See @docs/PROJECT_CONTEXT.md for the full background and the church→school feature mapping.
See @README.md for setup and run commands.

## Stack (do not swap without asking)
- Next.js 16 (App Router), React 19, TypeScript
- Payload CMS 3 (embedded — admin lives at `/admin`, same app)
- PostgreSQL via `@payloadcms/db-postgres`
- Lexical rich text (`@payloadcms/richtext-lexical`)
- Tailwind CSS + shadcn/ui for the public UI (add when styling; not yet installed)

## Project layout
- `src/payload.config.ts` — single source of truth (collections, globals, db)
- `src/collections/` — one file per collection (Users, Media, Pages, Posts, Galleries, Videos, Faculty, Students)
- `src/globals/` — SiteSettings, Header, Footer
- `src/blocks/` — reusable Page layout blocks (Hero, RichTextBlock, ImageText, Timeline)
- `src/access/index.ts` — shared access-control functions; ALWAYS reuse these, don't inline access logic
- `src/app/(frontend)/` — public site (Server Components reading via Payload Local API)
- `src/app/(payload)/` — Payload admin UI (generated by create-payload-app; do not hand-edit)

## Conventions
- Read/write data with the **Local API** (`getPayload({ config })` then `payload.find/findGlobal`) in Server Components — no fetch to `/api`.
- Public pages use ISR: `export const revalidate = 60`. The student portal is `force-dynamic`.
- Every collection sets explicit `access` using helpers from `src/access`. Never leave access undefined.
- Content that the public reads (posts, pages) uses draft versions + `adminsOrPublished` read access.
- Run `pnpm generate:types` after changing any collection/global, then use the generated types.
- Slugs are lowercase-kebab, stored in a `slug` field, unique + indexed.

## IMPORTANT — security rules
- The `students` collection holds PII. NEVER make it publicly readable. Read access is
  `ownStudentRecordOrAdmin` only. Do not add public endpoints that expose student data.
- The church/school auth idea (ID + Date of Birth) is WEAK. Do NOT ship DOB as a sole
  credential. For production, keep Admission/Membership No as the identifier but add a
  one-time code (email/SMS/WhatsApp) + rate limiting + lockout before exposing records.
- NEVER commit `.env`. Secrets only via environment variables.

## When building a feature
1. Add/adjust the collection or global first; regenerate types.
2. Verify it in the running `/admin` panel.
3. Build the matching public page under `src/app/(frontend)/`.
4. Keep one concern per change; small commits.

## Commands
- Dev: `pnpm dev` (admin at http://localhost:3000/admin)
- Types: `pnpm generate:types`
- Build: `pnpm build`
